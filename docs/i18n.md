# UI 다국어(i18n) 작업 절차

문구는 `src/shared/i18n/`에만 둔다(main·renderer 공용). 화면 코드는 `t('키')`(renderer `src/renderer/i18n.ts`) 또는 `tr('키')`(main·shared)로 읽는다.

| 파일 | 역할 |
|---|---|
| `registry.ts` | 지원 언어 목록 `LANGS`(코드·네이티브명·영어명·`intlLocale`·`default`·`script`·`fontFallback`·`aliases`·사전), 원문 언어 `SOURCE_LANG`(ko), 대체 언어 `FALLBACK_LANG`(en). `Lang` 타입은 이 배열에서 도출 |
| `ko.ts` | 원문 사전 = 키 집합의 기준 |
| `<코드>.ts` | 언어별 사전(`Dict` 타입: 원문의 모든 키 필수, 누락·오타는 컴파일 오류) |
| `index.ts` | `t`/`tr`, 복수형 선택, 로케일 매칭, 검색, Intl 날짜·숫자 도우미 |

대화상자 목록·검색, 시스템 로케일 매핑, `settings.json`의 `language` 검증, 사전 검사 테스트(`tests/unit/i18n.test.ts`)는 모두 `LANGS`를 순회한다. 언어 코드를 다른 곳에 쓰지 않는다.

## 새 언어 추가

1. `src/shared/i18n/<코드>.ts`를 만든다. 코드는 BCP 47 태그 그대로(`fr`, `pt-BR`, `es-419`), 파일 이름 = 코드. 내용은 `en.ts`를 복사해 번역하고 `export const <식별자>: Dict = { … }`.
2. `registry.ts`에 import 1줄 + `LANGS`에 1줄:
   `{ code: 'pt-BR', native: 'Português (Brasil)', english: 'Portuguese (Brazil)', intlLocale: 'pt-BR', default: true, dict: ptBR },`
   - `default`: 같은 언어(첫 하위 태그)의 변형이 여럿이면 하나에만 `true`(예: `es-419`). Windows 로케일이 정확히 맞지 않을 때(`es-MX`, 지역 없는 `es`) 이 변형을 고른다. 매핑 순서: ① 전체 태그 일치 → ② 같은 언어의 default 변형(없으면 첫 변형) → ③ `FALLBACK_LANG`. 변형이 하나뿐인 언어(`fr`·`de` 등)는 `fr-CA`·`de-CH`처럼 지역이 달라도 ②로 그 언어가 된다.
   - `aliases`: 같은 언어를 가리키는 옛·대체 언어 하위 태그(소문자 2~3자). ②에서 같은 언어로 본다. 예: `fil` ← `tl`(Tagalog, `tl-PH` → `fil`), `id` ← `in`(ISO 639 옛 코드). 매핑에만 쓰고 `settings.json` 값으로는 받지 않는다. 다른 등록 언어의 첫 하위 태그와 겹치면 테스트가 실패한다.
   - `script`: 같은 언어의 변형이 문자 체계로 갈리면(중국어) ISO 15924 코드를 적는다(`zh-TW` → `Hant`, `zh-CN` → `Hans`). ②에서 시스템 로케일의 스크립트 하위 태그(`zh-Hant-HK`) 또는 언어별 지역→스크립트 표(`index.ts` `REGION_SCRIPT`: zh TW·HK·MO → Hant, CN·SG·MY → Hans / pa PK → Arab)와 같은 변형을 먼저 고르고, 모르면(`zh`) default 변형. 태그의 문자 체계를 아는데 그 언어의 등록 변형이 **모두** `script`를 갖고 있고 하나도 맞지 않으면 ③(영어)으로 간다(예: pa는 `script: 'Guru'`뿐이라 pa-PK·pa-Arab-PK → 영어). 문자 체계가 여럿인 언어를 추가하면 모든 변형에 `script`를 적는다.
   - `intlFallback`: Electron 번들 ICU에 그 로케일 데이터가 없으면(아래 `npm run itest:intl`로 확인) 대체 Intl 로케일을 적고(pa → `'en-IN'`), `relativeDays`에 오늘·어제 낱말을 Node에서 `new Intl.RelativeTimeFormat('<intlLocale>', { numeric: 'auto' }).format(0, 'day')`·`format(-1, 'day')`로 얻은 값 그대로 넣는다.
   - `fontFallback`: Segoe UI로 못 그리는 문자면 Windows 글꼴을 넣는다(라틴 글꼴 뒤·Malgun Gothic 앞에 들어감). 예: 일본어 `Yu Gothic UI`, `Meiryo` / 인도계 문자 `Nirmala UI` / 태국어 `Leelawadee UI` / 암하라어 `Ebrima` / 중국어 번체 `Microsoft JhengHei UI`, 간체 `Microsoft YaHei UI`.
3. `npm test` — 키 집합·빈 값·보간 토큰·복수 범주 검사가 새 언어에도 자동으로 돈다. 대화상자 목록은 영어 이름 알파벳순으로 자동 정렬된다. 단, `tests/unit/i18n.test.ts`의 스냅샷 3곳(`LANGS 표시 이름` 기대값, `filterLangs` 전체 정렬 순서, 검색 `'an'` 결과)은 직접 갱신한다.
   - 새 `intlLocale`은 vitest(Node)뿐 아니라 **Electron 런타임에서도** 확인한다(`npm run itest:intl`, 소스 `tests/integration/intl-itest.ts`). Node는 full ICU라 Electron 번들 ICU에 없는 로케일도 정상처럼 보인다.
4. 아래 "번역 검수 체크리스트"로 화면을 확인한다.

## 키 추가·변경 규칙

- 새 문구는 `ko.ts`와 **등록된 모든 언어 사전**을 같은 변경에서 함께 수정한다(빠지면 컴파일 오류).
- 보간은 `{이름}`. 등록된 모든 언어가 같은 토큰을 써야 한다(어순은 언어마다 자유).
- 수가 들어가는 문구는 문자열 연결 대신 **복수형 객체**로 쓰고 수는 `{n}`: `ko`·`ja` `{ other: '탭 {n}개' }`, `en` `{ one: '{n} tab', other: '{n} tabs' }`. 각 언어는 `Intl.PluralRules(intlLocale)`의 범주를 빠짐없이·그것만 가진다(러시아어 `one/few/many/other`, 아랍어 `zero/one/two/few/many/other` 등, 테스트가 검사).
- 숫자 보간 값은 `Intl.NumberFormat`으로 자릿수 구분이 붙는다. PID·HTTP 상태·종료 코드처럼 식별자인 수는 `String(x)`로 넘긴다.
- 날짜·시각·퍼센트·숫자는 `formatDate`·`formatPercent`·`relativeDayName`(오늘·어제)(Intl, 현재 언어)만 쓴다. `${y}-${m}-${d}` 같은 수동 포맷 금지. 시각은 24시간제 고정.
- "n분 전" 같은 상대 시간은 Intl.RelativeTimeFormat 대신 사전 복수형 `time.minutesAgo`·`time.hoursAgo`·`time.daysAgo`(Intl 기본 출력이 어색한 언어가 있음, 예 ja "5 分前").
- 상태로 오래 남는 main 안내(탭 오류·사용량 오류·셸 경고)는 `msg(key, params)`로 번역 전 문구를 저장하고 보낼 때 `resolveMsg`로 번역한다(언어를 바꾸면 다시 번역됨).
- **상태 라벨은 명령형으로 옮기지 않는다**: 버튼처럼 보여도 상태·진행을 나타내는 키는 형용사·분사·진행형으로 번역한다. 대상: `sessions.open`(열림, `sessions.detached`와 짝) · `sessions.detached` · `status.*` · `hist.archived` · `hist.stopping` · `hist.block*` · `tab.ending` · `tab.leadGone` · `logout.busy` · `common.saving`/`loading`/`opening` · `agents.reading`/`savingLeader` · `trash.moving` · `grid.starting`/`waiting`. 예: fr `sessions.open` « Ouverte dans un onglet »(× « Ouvrir … »), nl 진행 상태는 « Bezig met opslaan… »처럼 버튼(« Opslaan »)과 구분.
- **런타임 조립 문구는 조립 결과가 문법적으로 성립해야 한다**: `open.runningElsewhere`+`open.where*`, `ipc.failed`+`action.*`, `set.*`+`{label}`은 전치사·관사를 `where*`/`action.*` 쪽에 넣는다(it·pt-BR 사례: 'nella sessione…', 'na sessão…').
- **로그인/로그아웃 어휘는 '연결 끊김(disconnected)' 상태 어휘와 겹치지 않게 한다**: it 'disconnesso'는 연결 끊김 전용, pt-BR 'conectado/desconectado'는 로그인 맥락 금지, es 'Iniciando sesión'은 로그인 전용 → 세션 시작은 'Creando la sesión'.
- 번역하지 않는 것: 카드 입력창 placeholder·Send, 터미널 내용, `AGENT_TEMPLATE`, 리드 명령 기본값, 로그(`logger`) 문구, 설정 키 이름, 제품·명령 이름(psmux, Claude Code, `claude auth login` 등), 단축키 표기(Ctrl+Shift+B).

문체(1·2라운드): 영어는 버튼·메뉴 Title Case, 문장·라벨 Sentence case, 마침표는 완전한 문장에만. 일본어는 です・ます, 메뉴·버튼은 체언 종결, 일본어 문장 안 괄호는 전각（）·영숫자는 반각. 스페인어·포르투갈어는 버튼·메뉴도 첫 글자만 대문자, 사용자 호칭은 tú(es)·você(pt), 복수형 `one/many/other`(`many`는 100만 단위 "1.000.000 de días").

문체(3라운드, 모두 버튼·메뉴도 첫 글자만 대문자 — 독일어는 명사 대문자):

bn·mr의 `intlLocale`에 `-u-nu-latn`을 붙이는 이유: CLDR 기본 숫자가 고유 숫자(벵골·데바나가리)라서, Intl이 만든 숫자를 앱의 다른 숫자 표기와 문구 안에 직접 넣은 숫자(라틴)에 맞추려고 라틴 숫자를 강제한다. `<html lang>`과 언어 선택 대화상자 버튼의 `lang`은 `langTag(lang)` = `new Intl.Locale(intlLocale).baseName`(`-u-…` 확장 제거: bn → bn-IN, mr → mr-IN)을 쓰고 `intlFallback`은 쓰지 않는다(pa는 계속 pa-IN). Intl 날짜·숫자 포맷은 `formatLocale(lang)`(`intlLocale`, `hasIcuData` 실패 시 `intlFallback`), 복수형 선택은 항상 `intlLocale`(pa 사전은 pa 복수 규칙을 따름: 0 = `one`).

런타임 ICU 데이터 유무 판정(`index.ts` `hasIcuData`, `intlFallback`이 있는 언어만): ① `Intl.DateTimeFormat.supportedLocalesOf`에 들어 있고 ② 해석된 로케일의 첫 하위 태그가 같고 ③ 긴 월 이름이 ICU root 자리표시("M10")가 아닐 때만 데이터가 있다고 본다. Electron은 pa-IN을 지원한다고 보고하고 'pa'로 해석까지 하지만 실제로는 root 데이터를 내므로 ①·②만으로는 못 가린다.

`ipc.failed` + `action.*` 조립(새 action 키를 넣을 때 언어별 형태를 맞출 것): fr `Impossible {what}` + 전치사 포함 부정사(« d'ouvrir la session »), de `Fehler beim {what}` + 명사화 부정사(Öffnen der Sitzung), nl `Fout bij {what}` + "het …"(het openen van de sessie), it·id·vi·fil 부정사(aprire la sessione / membuka sesi / mở phiên / buksan ang session), tr `{what} başarısız oldu` + 대문자로 시작하는 -ma/-me 동명사(Oturumu açma). 4라운드: zh-CN `{what}失败：{msg}` + 동목 구(打开会话), zh-TW `無法{what}：{msg}` + 동목 구(開啟工作階段), ru `Не удалось {what}` / uk `Не вдалося {what}` + 소문자 부정사(открыть сеанс / відкрити сеанс), da·nb `Kunne ikke {what}` / sv `Det gick inte att {what}` + at/att 없는 부정사(åbne sessionen / öppna sessionen / åpne økten), fi `{what} epäonnistui` + 대문자로 시작하는 동명사 명사구(Istunnon avaaminen). 5라운드: hi `{what} में विफल` / pa `{what} ਵਿੱਚ ਅਸਫਲ` + 사격(oblique) 부정사(सत्र खोलने / ਸੈਸ਼ਨ ਖੋਲ੍ਹਣ), bn `{what} যায়নি` + 동명사(সেশন খোলা), ta `{what} முடியவில்லை` + -க்க 부정사(அமர்வைத் திறக்க), te `{what} విఫలమైంది` + 동명사 주어(సెషన్‌ను తెరవడం), mr `{what} अयशस्वी` + -ण्यात형(सत्र उघडण्यात), gu `{what} શક્યાં નહીં` + 접속분사(સત્ર ખોલી), kn `{what} ಸಾಧ್ಯವಾಗಲಿಲ್ಲ` + -ಲು 부정사(ಸೆಷನ್ ತೆರೆಯಲು), ml `{what} കഴിഞ്ഞില്ല` + -ാൻ 부정사(സെഷൻ തുറക്കാൻ).

일본어 문장에서 ` — ` 연결은 쓰지 않고 「。」(문장 경계)·「：」(라벨 뒤)로 잇는다. 세션 이름 등 고유값 인용은 「」.

지역 변형: 같은 언어의 두 번째 변형은 대표 변형 사전을 펼친 뒤 차이만 덮어쓴다(`es-ES.ts` = `{ ...es419, 차이 }`). 대표 변형에 키를 추가하면 자동으로 물려받으므로, 그 변형에서 표현이 달라지는지만 확인한다.

## 번역 검수 체크리스트

1. **용어 일관성**: 위 용어표와 다른 표현이 없는지 사전 파일에서 검색(예: 영어 `disconnect`가 "세션 끊기"에 쓰이지 않았는지).
2. **복수형**: `{n}` 문구를 1·2·5·21처럼 범주가 갈리는 수로 확인(`t('<코드>', 'tab.working', { n: 21 })`). 화면 코드에서 수를 문구에 문자열로 이어 붙인 곳이 없는지.
3. **길이**: 원문보다 1.5~2배 길어질 수 있다(독일어·러시아어 등). 사이드바 최소 폭(200px)·창 최소 크기(1028×672)에서 계정 ⋯ 메뉴, 히스토리 ⋮ 메뉴, 필터 메뉴(2단계 포함), 탭 바(작업 중 뱃지), 사용량 영역, 설정·Agents 대화상자 버튼을 연다. 메뉴 항목은 줄바꿈, 한 줄 요소(탭 이름·버튼·뱃지·사용량 라벨)는 말줄임이 정상이고 겹침·잘린 글자 위아래가 없어야 한다. 영어 사전의 긴 문구(`card.stopMate` "Ask the CEO to Stop This Teammate", `menu.sessions`)로 카드 ⋮·계정 ⋯ 메뉴를 먼저 확인한다.
4. **글꼴**: 그 언어로 바꾼 뒤 개발자 도구(개발 실행 시) Elements → `<html>`의 `lang`과 `--font-ui` 값을 확인하고, Rendered Fonts에 의도한 글꼴(예: 일본어 Yu Gothic UI)이 나오는지 본다. 한자·가나가 한국어 글꼴 모양(Malgun Gothic)으로 나오면 `fontFallback` 누락.
5. **날짜·숫자**: 사이드바 시각 열(오늘·어제·올해·작년 항목), 사용량 갱신 시각·퍼센트·초기화 시각 툴팁이 그 로케일 형식인지.
6. **main 안내**: 설정 대화상자에서 잘못된 경로 저장(검증 오류), 없는 폴더로 새 세션(오류 줄), 언어 변경 후 끊긴 탭의 툴팁(탭 오류가 새 언어로 바뀌는지).
7. **수신 관계**: 목적어에 여격 표지를 따로 붙이지 않는 언어(hi·mr·pa에서 관찰)에서 `stopMate.detail`("CEO 카드에게 보내는 요청")이 "CEO 카드를 *멈추라는* 요청"으로 오독된 적이 있다. "누구에게 보내는지"가 모호하지 않은지 확인한다.
8. **인도계 글꼴·짧은 라벨**: 검수자는 길이를 글자 수로만 판단했으므로 실제 화면에서 개발자 도구 Rendered Fonts에 Nirmala UI가 나오는지, 탭 뱃지(작업 중)·상태 칩 같은 짧은 라벨이 잘리지 않는지 확인한다.

## 참고 사항

- Electron 번들 ICU에 펀자브어(pa) 데이터가 없다: pa는 런타임 ICU에 `intlLocale` 데이터가 없으면 `intlFallback: 'en-IN'`으로 Intl 날짜·숫자를 포맷하고, 오늘·어제 낱말은 registry의 `relativeDays` 값을 쓴다. 언어를 추가할 때는 `npm run itest:intl`을 반드시 돌린다.
- pa-PK / pa-Arab-PK(샤무키 문자)는 의도적으로 영어로 대체된다: pa 항목 `script: 'Guru'` + `REGION_SCRIPT` `pa: { pk: 'arab' }` + `matchLang` 규칙("태그의 문자 체계를 알고, 그 언어의 모든 변형이 `script`를 갖고, 하나도 맞지 않으면 일치 없음 → 영어"). 감수한 부작용: `zh-Latn`도 zh-CN 대신 영어가 된다.
- Windows 공식 용어 대조(Microsoft Terminology Collection TBX 2024-11): 출처가 분명한 불일치만 반영(gu·kn·ta 휴지통, kn·ta·pa 밝게/어둡게, kn Refresh, te Refresh 표기, hi 앱 정보). 보류: mr 저장 सुरक्षित(“안전한”과 겹침), hi·mr·gu Refresh(구 항목뿐), te 저장, pa 파일 ਲਿਖਤ ਪੱਤਰ, mr·gu 복원 표기, te ప్రదర్శన가 Appearance·표시 이름 겸용. 로그인/로그아웃은 Claude 계정(`claude auth login`)이라 Windows의 Sign in 대신 Log in 유지. 환경 변수·Appearance·다시 시도·시스템 설정 사용은 공식 항목 없음
- 마라티어 "앱"은 ॲ(U+0972 DEVANAGARI LETTER CANDRA A)로 쓴다. अ+ॅ(U+0905 U+0945) 조합은 Nirmala UI에서 한 글자로 합쳐지지 않는다. 경로 입력칸 안내 문구는 UI 글꼴(--font-ui)로 표시한다
